# Configuration API

Catalyst reads runtime and build configuration from `config/config.json`. This page covers the contract that the framework expects. For a guided walkthrough, see [Configuration](/content/02-Guides%20and%20Tutorials/01-First%20Catalyst%20App/04-Configuration.mdx).

## Top-Level Configuration

These keys are part of the core web runtime:

| Key | Type | Required | Purpose |
|-----|------|----------|---------|
| `NODE_SERVER_HOSTNAME` | `string` | Yes | Hostname for the Node SSR server |
| `NODE_SERVER_PORT` | `number` | Yes | Port for the Node SSR server |
| `BUILD_OUTPUT_PATH` | `string` | Yes | Output directory for production assets |
| `PUBLIC_STATIC_ASSET_PATH` | `string` | Yes | Public mount path for static assets |
| `PUBLIC_STATIC_ASSET_URL` | `string` | Yes | Base URL for emitted static assets |
| `CLIENT_ENV_VARIABLES` | `string[]` | Yes | Variables that should be exposed to the client bundle |

Application-specific values such as `API_URL` can also live in this file. They are available on the server through `process.env`.

## Client-Exposed Environment Variables

Catalyst does not expose every config key to browser code automatically. Add the keys you want available on the client to `CLIENT_ENV_VARIABLES`.

```json title="config/config.json"
{
  "API_URL": "https://api.example.com",
  "ANALYTICS_ID": "UA-123456",
  "DATABASE_URL": "postgresql://internal-db",
  "CLIENT_ENV_VARIABLES": ["API_URL", "ANALYTICS_ID"]
}
```

In this example:

- `process.env.API_URL` is available on both server and client.
- `process.env.ANALYTICS_ID` is available on both server and client.
- `process.env.DATABASE_URL` stays server-only.

Keep this list small. Any key included here becomes visible in the client bundle.

## Required Universal App Fields

### Shared fields

| Key | Required | Notes |
|-----|----------|-------|
| `WEBVIEW_CONFIG.port` | Yes | Port the native WebView should load |
| `WEBVIEW_CONFIG.LOCAL_IP` | Yes | Use your LAN IP, not `localhost` |
| `WEBVIEW_CONFIG.appInfo` | Yes | Build identifier used by native tooling |
| `WEBVIEW_CONFIG.useHttps` | No | Defaults to `false` |
| `WEBVIEW_CONFIG.profiler.enabled` | No | Enables the debug-only Catalyst Profiler; defaults to `false` |
| `WEBVIEW_CONFIG.release` | Yes for store builds | Production overrides, deep-merged over `WEBVIEW_CONFIG` for Android and iOS release builds only. Usually sets `LOCAL_IP`, `port`, `useHttps` and `apiBaseUrl`, and can override `android` and `ios` fields |
| `WEBVIEW_CONFIG.release.allowPrivateHost` | No | `true` lets a release start URL use a private or local host (internal apps). Defaults to `false` |

### Android fields

| Key | Required | Notes |
|-----|----------|-------|
| `WEBVIEW_CONFIG.android.sdkPath` | Yes | Absolute path to the Android SDK |
| `WEBVIEW_CONFIG.android.emulatorName` | Yes for debug | Required for emulator-based debug builds |
| `WEBVIEW_CONFIG.android.buildType` | No | `debug` or `release`. `buildApp:android --release` also builds release |
| `WEBVIEW_CONFIG.android.packageName` | Yes for release | Application id for release and debug builds (debug adds `.debug`) |
| `WEBVIEW_CONFIG.android.version` | No | `{ major, minor, patch, buildNumber }`, the same shape as `ios.version`. Without it the version name comes from `package.json` |
| `WEBVIEW_CONFIG.android.signing.storeFile` | No | Upload keystore path, relative to the app. Defaults to `credentials/android/upload.jks` |
| `WEBVIEW_CONFIG.android.signing.keyAlias` | No | Upload key alias. Defaults to `upload` |
| `WEBVIEW_CONFIG.android.keystoreConfig.organizationInfo` | No | Certificate details used when Catalyst creates the upload key. Passwords here are no longer used |
| `WEBVIEW_CONFIG.android.buildOptimisation` | No | Enables Android build optimisation, in release builds too |

### iOS fields

| Key | Required | Notes |
|-----|----------|-------|
| `WEBVIEW_CONFIG.ios.appBundleId` | Required for distribution | Set this explicitly for release builds |
| `WEBVIEW_CONFIG.ios.buildType` | No | `debug` or `release`, in any case. `release` builds the store IPA like `buildApp:ios --release` |
| `WEBVIEW_CONFIG.ios.version` | No | `{ major, minor, patch, buildNumber }`. Without it the version comes from `package.json` |
| `WEBVIEW_CONFIG.ios.simulatorName` | No | Used for simulator builds |
| `WEBVIEW_CONFIG.ios.deviceUDID` | No | For physical device builds |
| `WEBVIEW_CONFIG.ios.developmentTeam` | Yes for device and release builds | Apple team ID. With no `provisioningProfile`, Xcode signs automatically for this team |
| `WEBVIEW_CONFIG.ios.provisioningProfile` | No | Profile name for manual signing. Put the App Store profile in `release.ios.provisioningProfile` |
| `WEBVIEW_CONFIG.ios.ascApiKey` | No | `{ path, keyId, issuerId }` of an App Store Connect API key, so automatic signing works without an Apple account in Xcode. Keep the `.p8` outside the repository |
| `WEBVIEW_CONFIG.ios.exportMethod` | No | How the release archive is exported: `app-store-connect` (default), `release-testing`, `enterprise` or `debugging` |
| `WEBVIEW_CONFIG.ios.cachePattern` | No | Array of glob-style URL patterns (e.g. `["*.css", "*.js"]`) the native WebView cache should match — a single string is treated as one literal pattern, not comma-split; when unset, no pattern-based caching is enabled (offline-route caching can still apply) |

## Access Control

Use `WEBVIEW_CONFIG.accessControl` to whitelist outbound URLs used by the WebView and native request flows.

```json
{
  "WEBVIEW_CONFIG": {
    "accessControl": {
      "enabled": true,
      "allowedUrls": [
        "*.yourdomain.com*",
        "https://api.example.com/*",
        "http://localhost:*"
      ]
    }
  }
}
```

If you enable access control, make sure every required API, CDN, and localhost URL is included.

## Splash Screen

The splash screen configuration belongs inside `WEBVIEW_CONFIG.splashScreen`, not at the top level of `config.json`.

| Key | Type | Notes |
|-----|------|-------|
| `backgroundColor` | `string` | Defaults to white |
| `duration` | `number` | Primarily relevant on iOS. Ignored when `public/splashscreen.html` exists |
| `minDuration` | `number` | Minimum time in ms the HTML splash stays on screen. Defaults to `0` |
| `imageWidth` | `number` | Width of the splash asset |
| `imageHeight` | `number` | Height of the splash asset |
| `cornerRadius` | `number` | iOS rounded corners |

Place splash assets at:

- `public/android/splashscreen.{png|jpg|jpeg|gif|bmp|webp}`
- `public/ios/splashscreen.{png|jpg|jpeg}`
- `public/splashscreen.html` (optional, shared by both platforms)

When `splashScreen` is set and `public/splashscreen.html` exists, the app shows the native image first, then the HTML splash, and switches to the app once its first page has loaded and `minDuration` has passed. The HTML splash is dismissed after 10 seconds even if the page is still loading. The file must be self-contained, with inline CSS and JavaScript and images as `data:` URIs. It has no access to the native bridge and should not make network requests, which Android blocks. Remove the file to go back to the image-only splash. See [Universal App Configuration](/content/02-Guides%20and%20Tutorials/02-First%20Universal%20App/03-Configuration.mdx) for the full rules and an example.

## Validation Notes

- Missing required top-level config keys cause startup failures.
- Using `CLIENT_ENV_KEYS` is outdated. The current key is `CLIENT_ENV_VARIABLES`.
- `ios.buildType` accepts `debug` or `release` in any case. `release` makes `buildApp:ios` build the store IPA instead of running the app.
- `LOCAL_IP` should be a reachable LAN IP for emulator or device builds. Put the production host in `WEBVIEW_CONFIG.release`.
- A release build fails when its start URL points at a local or private host, or when it has no build number. See [Universal App Deployment](/content/08-Deployment/02-Universal-App-Deployment.md) and [iOS Production Release](/content/08-Deployment/03-iOS-Production-Release.md).
- `WEBPACK_DEV_SERVER_HOSTNAME`, `WEBPACK_DEV_SERVER_PORT`, and `ANALYZE_BUNDLE` are no longer required or read, so you can delete them or leave them in place.
